# StrongHold

StrongHold keeps your identity documents (Aadhaar, PAN, Driving License, Class X / XII marks
cards and more) in an **encrypted, sandboxed vault** and later helps you fill government forms
through a guided, in-app assistant.

> **Status: Frontend foundation (React Native / TypeScript).**
> Native security modules (Android Keystore AES) and the LLM / VLM assistant layers are not wired
> yet. All UI flows run on in-memory mock data so the screens can be navigated end to end.

## Product concept

- **Encrypted vault** — documents stored in an app-private sandboxed folder, encrypted with
  AES-256-GCM. The key is generated in the Android Keystore (hardware-backed, TEE) and never
  leaves the device.
- **Form assistant** — an LLM that opens a government form in a guided WebView overlay, uses VLM
  to read the page, and flags malicious forms or fields that should not be filled.
- **Languages** — Bhashini API for regional-language conversations; SwytchCode APIs for live
  interactions (to be added).

## Stack

- React Native `0.76.x` + TypeScript (strict)
- React Navigation 7 (native stack + bottom tabs)
- react-native-safe-area-context, react-native-screens
- No icon/image libraries — all glyphs and icons are drawn with plain `View`s (see
  `src/components/Icon.tsx`)

## Getting started

> Native `android/` and `ios/` folders are generated by the React Native CLI. This repo contains
> the JavaScript/TypeScript layer only.

```bash
# 1. Generate the native shell (creates android/ and ios/ folders)
npx @react-native-community/cli init StrongHoldNative --version 0.76.9 --skip-install
cp -r StrongHoldNative/android StrongHoldNative/ios .
rm -rf StrongHoldNative

# 2. Install dependencies
npm install

# 3. Type-check
npm run typecheck

# 4. Run on Android (emulator or connected device)
npm run android
```

Alternatively point the generated `android/app` at this project by copying the `src/`, `App.tsx`,
`index.js` and config files into a freshly generated project.

## Project layout

```
  types/                    # shared domain types
  data/                     # mock documents + mock forms
  context/                  # AuthContext (onboarding/lock/unlock), VaultContext (in-memory store)
  components/               # design-system components (Button, Card, Chip, Icon, PinPad, ...)
  screens/
    onboarding/             # 3-slide intro
    auth/                   # PIN lock screen
    vault/                  # vault home, add document, document detail
    assistant/              # form assistant (preview UI)
    settings/               # security & preferences
  navigation/               # root stack + bottom tabs + param types
  utils/                    # formatting helpers
```

## App flow

1. **Onboarding** → 3 feature slides.
2. **Lock screen** → create a 6-digit PIN on first run, then unlock with it (any mismatch shakes
   and errors). PIN is kept in memory for the demo.
3. **Vault** → search + category filters, add documents (type picker, scan mock), view detail with
   masked fields and reveal toggle, delete with confirmation.
4. **Assistant** → language chips (Bhashini), safety explainer, chat preview, and a form list with
   `Verified safe` / `Review carefully` / `Blocked` verdicts.
5. **Settings** → security toggles, export/clear vault (mock), language, about, lock now.
